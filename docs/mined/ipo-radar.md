## A. PDF extraction of SEBI prospectuses

### A1. Libraries and how they're combined
- `backend/requirements.txt` / `automation/requirements.txt`: `pymupdf>=1.24`, `pdfplumber>=0.11`, `rapidfuzz>=3.6`. OCR = `pytesseract` + `PIL`, optional (not in requirements).
- **PyMuPDF (fitz)** does the single full pass: `backend/app/pipeline/pdf_processor.py:28-52` `process_pdf()` opens the doc once, `page.get_text("text")` per page (line 35), `doc.get_toc(simple=True)` for bookmarks (line 43). Output: `{"page_count", "pages":[{"n":1-indexed,"text"}], "toc":[{level,title,page}], "low_text_pages", "readable_ratio"}`.
- **OCR**: pages with `< 40` chars (`LOW_TEXT_THRESHOLD`, line 12) are "image pages"; only if `ENABLE_OCR=1` (`backend/app/config.py:41`) does `_ocr_page()` (lines 15-25) rasterize at 300 dpi and run tesseract. Default off ("most mainboard RHPs are born-digital").
- **pdfplumber** is used only for **tables**, and only on already-located page ranges: `financial_extractor.py:268-303` (`pdfplumber.open(pdf_path)`, `pdf.pages[n-1].extract_tables()`), `entity_extractor.py:131-164` (shareholding table), `:216-219` (peers), `:274-277` (issuer EPS), `:393-395` (note totals). The PDF is re-opened by pdfplumber separately from fitz; the per-page plain text from fitz is passed alongside (`pages[n-1]["text"]`) and used for unit detection / borderless fallback.
- Division of labour: fitz = text + bookmarks + page indexing; pdfplumber = ruled tables on <~40 targeted pages; regex over fitz text for everything else.

### A2. Bookmarks / TOC → chapter location
File: `backend/app/pipeline/section_extractor.py` (194 lines, self-contained, the most reusable piece).
- `CANONICAL_SECTIONS` (lines 14-71): 27 SEBI-ICDR chapter keys, each with `synonyms` (for fuzzy TOC matching) and a strict `heading` regex (for page-top scan). Keys/synonyms:
  offer_summary ("offer document summary", "summary of the offer document"), risk_factors, general_information, capital_structure, objects_of_offer ("objects of the offer/issue"), basis_for_offer_price ("basis for offer/issue price"), tax_benefits, industry_overview ("industry overview","our industry"), our_business, key_regulations, history_corporate, management, promoters ("our promoters and promoter group"…), group_companies, dividend_policy, financial_statements ("restated financial statements/information"…), other_financial_info, capitalisation, indebtedness, mdna, litigation, government_approvals, regulatory_disclosures, **terms_of_offer** ("terms of the offer/issue"), **offer_structure** ("offer structure","issue structure"), **offer_procedure**, material_contracts.
  Note: no "definitions and abbreviations", no "the offer" (cover summary table), no "main provisions of articles".
- Three-tier fallback, `extract_sections(pages, toc)` lines 156-187:
  1. `_from_bookmarks(toc)` lines 95-104: only bookmark levels ≤ 2, `rapidfuzz.fuzz.token_set_ratio(normalised_title, synonym) >= 82` (`FUZZY_THRESHOLD`, line 73); best score wins per key. `_normalize()` (76-78) strips "Section IV –" prefixes and non-letters.
  2. `_from_printed_toc(pages)` lines 107-123: for PDFs **without bookmarks** (or missing keys) it scans the first 15 pages for lines matching `^(.{4,80}?)[\s.·]{3,}(\d{1,4})\s*$` (title ..... pagenum), fuzzy-matches the title. Then `_verify_page()` lines 145-153 fixes printed-vs-physical page offsets (roman-numeral prelims) by scanning ±40 pages around the claimed page for the heading regex.
  3. `_from_heading_scan(pages, missing_keys)` lines 132-142: for still-missing keys, walk every page and test the first 12 lines (`_heading_on_page`, 126-129) against `^\s*(?:SECTION\s+[IVXLC]+\s*[-–:.]?\s*)?{heading}\s*$` (multiline). First page wins.
  - Spans: each section runs from its start page until the next located section's start (lines 170-181), text concatenated per section. Each record carries `method` ∈ {toc, printed_toc, heading_scan} which drives downstream confidence. Missing keys are returned with `found: False`.
  - `section_hit_rate()` (190-194) = fraction of 12 core chapters found; reports in the repo show 0.92 typical.
- Weakness to note: heading scan takes the *first* page whose top lines match, so "RISK FACTORS" can hit the TOC page or a cross-reference; the ±40-page `_verify_page` only applies to printed-TOC hits.

### A3. Table extraction (financials / price band / peers)
- **Restated financials** – `financial_extractor.py`:
  - Anchor pages: `find_statement_pages()` 241-256 searches the first 2500 chars of every page inside `financial_statements`, `other_financial_info`, `offer_summary` spans for `STATEMENT_ANCHORS` regexes (47-55: "restated (consolidated|standalone) statement of profit and loss / assets and liabilities / cash flows", "summary of restated financial information", "balance sheet"…). Falls back to whole-doc scan if no sections found.
  - For each anchor page **+ the following 3 pages** (line 270) it runs `page.extract_tables()` (303). Header row = first of the top 4 rows with ≥2 cells matching `FY_HEADER_RE` ("March 31, 2025", "Fiscal 2025", "FY25"; 62-63) → column→FY map (`_fiscal_labels_from_header`, 112-124). Rows are labelled by `ROW_SYNONYMS` (16-45: revenue, other_income, total_income, employee_costs, finance_costs, depreciation, pbt, tax, pat, ebitda, total_assets, net_worth, borrowings lt/st, receivables, inventory, cash, current assets/liabilities, cfo/cfi/cff, capex). First value per (FY, metric) wins.
  - Unit normalisation to ₹ crore: `detect_unit()` 102-109 (lakhs/crores/millions/billions markers), and a nearest-marker rule across contiguous page runs (272-287) because one page of a statement block carries the unit for all.
  - **Borderless-table fallback** `_rows_from_text()` 173-238: when pdfplumber finds nothing, parse fitz text — a label line followed by N value lines (or values at end of the label line), with column count = number of FY headers found in the page's top 3000 chars (`_fy_labels_from_text`, 143-156, which also tags stub-period columns "December 31, 2025" as STUB so they are consumed but discarded). Handles Notes-column refs, dash cells, parenthesised negatives, Indian grouping (`parse_number`, 86-99).
  - Derived metrics (359-366): total_debt, ebitda, revenue from total_income.
- **Price band / issue details** – `entity_extractor.py:56-128` `extract_issue_details()`: pure regex over fitz text of cover pages (1-8) plus the `offer_structure`, `terms_of_offer`, `capital_structure`, `general_information`, `offer_summary`, `basis_for_offer_price` spans. Patterns: price band `price\s+band\s*[:of]*\s*₹\s*(\d)\s*(to|-)\s*₹?(\d)` (75); fixed-price fallback (80); face value (84); "fresh issue of … aggregating up to ₹X crore" (88) and "offer for sale of … aggregating" (92); lot size (99); listing_at NSE/BSE (103); pre/post-issue promoter % in prose (107-116) with a **table fallback** `_promoter_holding_from_tables()` 131-164 (first 25 pages of capital structure; header folded; last "%" column of a Pre|Post table; row label contains "promoter").
- **Peers** – `extract_peers()` 203-253: first 30 pages of `basis_for_offer_price`; `_fold_header()` 180-200 concatenates all rows above the first data row per column (headers wrap over 3-4 physical rows — author notes this fix took peer extraction from ~5% to working); requires header containing both P/E and EPS; columns located by regex; issuer row tagged `is_issuer`. `extract_issuer_eps()` 256-315 reads the EPS-by-year weighted table (EPS + Weight columns, no P/E column) and computes weighted average.
- Other: objects of offer (337-353, regex lines with amounts in first 10 pages of the chapter), litigation counts (356-372), RPT and contingent liability totals (419-457; prose regex, then table "Total" row via `_total_from_tables` with `_page_unit` caption unit), dividend, pledging, auditor qualification.

### A4. Performance / limits / caching / hashing
- Whole document is text-extracted once by fitz (no page cap); no parallelism. pdfplumber only touches targeted windows: anchor+3 pages for financials, ≤25 pages for shareholding, ≤30 for peers/EPS (`min(r[1]+1, r[0]+25/30)`).
- `_from_printed_toc` limited to first 15 pages; `_heading_on_page` only looks at the first 12 lines of a page.
- No PDF caching or PDF hash in the automation path. The API path computes SHA-256 while streaming the upload (`backend/app/api/routes.py:56-71`, stored on `Document.sha256`, `models.py:25`) but it is not used for dedup. CI downloads to a `TemporaryDirectory` and deletes the PDF (`automation/update.py:349-361`); only the compact report JSON persists (`docs/data/reports/<cg_ipo_id>.json`).
- Download validation: `curl -sL --retry 4 --retry-all-errors -C - --max-time 600`, must be ≥100 KB and start with `%PDF` (update.py:351-356).
- Per-run bounds: `MAX_NEW_RHP_PER_RUN = 6` (update.py:51), workflow timeout 55 min. `backfill_rhp.py` prints s/report; author comment: "one prospectus is a 400-page PDF", "it is slow".
- Upload limit `MAX_UPLOAD_MB=300`.

### A5. "The Offer" / Offer Structure / definitions — Eligible Shareholders clause
- **Nothing.** The repo never searches for "eligible shareholder", "shareholder reservation", "shareholders' reservation portion", "employee reservation" (grep across backend/automation returns none; only `employee_costs` in P&L rows). `parse_reservation()` in `automation/update.py:475-509` reads the QIB/NII/RII % split **from Chittorgarh's detail page HTML** (keys `shares_offered_qib_percentage` etc.), not the prospectus. `cg_subs.csv` does carry a `Shareholder (x)` and `Employee (x)` subscription column straight from Chittorgarh report 21, which is the only trace of a shareholder quota anywhere.
- Closest usable building blocks: the `offer_structure` / `terms_of_offer` / `offer_summary` section spans from `section_extractor.py` (lines 14-16, 63-68) — Offer Structure is the chapter whose table has the "Shareholders Reservation Portion" column/row, and the Definitions chapter (not in CANONICAL_SECTIONS; would need a new entry: synonyms "definitions and abbreviations", heading `DEFINITIONS AND ABBREVIATIONS`) is where "Eligible Shareholder(s)" is defined. `_fold_header()` in `entity_extractor.py:180-200` is the right tool for the Offer Structure table (its header wraps across rows: "Shareholders Reservation Portion" / "QIBs" / "Non-Institutional Bidders" / "Retail Individual Bidders").

## B. SEBI + data pipeline

### B6. SEBI RHP discovery & download (`automation/update.py`)
- Listing endpoint (POST, AJAX): `SEBI_AJAX = "https://www.sebi.gov.in/sebiweb/ajax/home/getnewslistinfo.jsp"` (line 48). Body (lines 323-324):
  `nextValue={page}&next=n&search=&fromDate=&toDate=&fromYear=&toYear=&deptId=&sid=3&ssid=15&smid=11&ssidhidden=15&intmid=-1&sText=Filings`
  (sid=3/ssid=15/smid=11 = Filings → Public Issues → Red Herring Documents). Referer `https://www.sebi.gov.in/sebiweb/home/HomeAction.do`, desktop Chrome UA (line 46), 1.0 s sleep between pages, 3 tries w/ backoff (`http()`, 58-71).
- `sebi_recent_entries(max_pages=8)` lines 317-331 parses rows with regex (318-320): `<td>Mon DD, YYYY</td> <td><a href="https://www.sebi.gov.in/filings/…" … title="…">` → `{date, url, title, toks}`; drops titles matching `corrigendum|addendum|notice|clarification`. `backfill_rhp.py:39-65` `sebi_archive(pages)` is the deep walk (page 40 ≈ 2007), also skipping "abridged".
- Listing → PDF: `fetch_and_analyze()` 339-362 GETs the filing detail page and tries `PDF_RES` (334-336) in order: `href="https://www.sebi.gov.in/sebi_data/…pdf"`, then `file=…pdf`, then any `href="…pdf"`, `urljoin`ed. Downloads with curl (see A4).
- Matching filing ↔ IPO: `ensure_rhp_reports()` 365-398 — for Chittorgarh IPOs opened in the last 270 days with no report, tokenise company name (`norm_tokens`, 78-82, drops ltd/limited/pvt/rhp/red/herring/prospectus/dated…), require `set(company_toks) <= filing_title_toks` and filing date within [open−200 d, open+45 d]; nearest date wins. Backfill uses −280 d.
- Observed bug/limit: Chittorgarh company strings now carry status suffixes ("Rentomojo Ltd. LT", "Hero Motors Ltd. O", "…Ltd. P") which become tokens "lt"/"o"/"p" that never appear in SEBI titles → subset match fails. Consistent with the data: reports exist for every IPO opened through 2026-09-01, none for the 20 IPOs opened 2026-09-07…09-24. Also SEBI's archive is mostly DRHPs, so the pipeline passes Chittorgarh's price in (`offer_price`) because the doc prints "[●]".
